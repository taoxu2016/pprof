### Scoping questions of the handoff

1. **CI first** (step 1, DEC-071). The check, reference, and coverage jobs have failed on every push since Phase 2 (F1), so criteria 1 and 9 cannot be shown until they pass, and every later step should be checked there too. The causes are unknown and are not guessed: step 1 reads the check results and logs, records each cause, and fixes it in the smallest scope. Three things need the project lead: (a) the artifacts and logs for the first diagnosis (F1 lists them); (b) pushes, since CI runs only on pushes and pull requests (a standing approval to push `rewrite/phase-8` to the fork, fast-forward only, is proposed, each push reported); (c) the sanitizer and benchmark jobs, which run only on pull requests or on demand (a dispatch from the Actions page, or the Phase 8 pull request). To read later runs without downloading anything, the check jobs gain a step that copies the failing sections of the check log into annotations, which the public API returns (DEC-071); the GitHub CLI would also do, but installing it is the project lead's decision and is not needed if the annotations work.
2. **Which wrappers stay: all of them** (DEC-072), as ARCHITECTURE §I.3 plans: 2.0.0 ships every function of pprof 1.0.3, warning once per session; they remain at least through 2.1.0; their removal is the owners' decision (M-12).
3. **The version: 2.0.0 on the branch from step 5** (DEC-077), the release candidate that the final review checks: with it, `R CMD check --as-cran` drops the version, Date, and NEWS items (F4). The `Date` field is removed (R CMD build records the date; a stale `Date` is a CRAN note). The alternative is a development version such as `1.0.3.9000` until the owners release, which `--as-cran` notes. "CRAN readiness" means: `R CMD check --as-cran` clean on every CI platform with any remaining note justified, a tarball under 5 MB, no example over 5 s, valid URLs or a release precondition for the owners, and `cran-comments.md`; the submission and its timing are the owners'.
4. **Minimum versions** (DEC-074). R: the package's own R code needs only R 4.0 (F12), but its dependencies' current versions need R ≥ 4.4 (Matrix 1.7-6, MASS 7.3-66) or ≥ 4.1 (ggplot2 4.0.3), and nothing below R 4.4.0 has been tested (F2). Proposed: a CI job at the declared minimum, R 4.1; if it cannot install the dependencies or fails, Linux jobs with oldrel-2 to oldrel-4 find the lowest R that passes, and `Depends` states that one, so that the requirement is true; the owners may set a higher one (M-12). ggplot2: `(>= 4.0.0)`, the version the plot fixtures and the plot guard were recorded under (D-36). lme4 and Matrix: no minimum beyond lme4's own; their version sensitivity is documented (the lme4-backed results are compared only under lme4 2.0-6 and Matrix 1.7-6, DEC-020).
5. **The slow examples: smaller data** (DEC-077). Seven old logistic RE and CRE examples take 5.5 to 6.4 s here (F4); they fit providers 1 to 20, as the new fits' examples do (under 1 s each, PHASE7_PLAN F7), and keep running under `R CMD check`; `\donttest{}` would leave them unchecked by default.
6. **clang-format: yes** (DEC-078), with a configuration close to the core's current style, applied in one commit that is shown to change only whitespace, and checked in CI. clang-format is not installed here (F3); installing it is the project lead's decision: proposed, the `clang-format` npm package (Node.js is installed) in a scratch folder, and the same package and version in CI; or LLVM through winget. Without it, step 7 is skipped and the final review lists brief §9's clang-format item as open.
7. **The methodology sign-offs** of the final review: below, "What the final review needs from the methodology owners".

Proposed in addition:

- **The tarball** (DEC-076, new finding). Built as 2.0.0, the tarball is 5,760,081 bytes, over the 5,000,000 at which `--as-cran` notes it (F4). The shipped fixtures make up 4.76 MB of the content, and four of their datasets, 1.33 MB, are copies of the bundled example data that the generator makes from `data/` (F5). Proposed: leave those four files out of the build, and have the fixture loader rebuild them from the bundled data as the generator does, checking the rebuilt object against the file wherever the file is present (in the repository and in CI's reference job). ## Risks

- **CI's causes are unknown.** A cause may be a real difference across platforms: a fixture comparison outside its tolerance on Linux would need a decision under the tolerance policy (step 1, case (c)), and a fault in the C++ core on Linux (the NaN reaching `median()`) would be a Class A defect to find with the sanitizers. Each iteration needs a push, and reading it needs the annotations of step 1 or downloaded logs.
- **The minimum R.** The dependencies' current versions may not install below R 4.4 (F2), so the declared R ≥ 4.1.0 may have to rise; that is the owners' to confirm (M-12). If the runners offer no R 4.1 for Ubuntu 24.04, that one job runs on `ubuntu-22.04`.
- **Deprecation in the tests.** Marking the warnings as given for the whole test run could hide a missing warning; the dedicated test file checks each one with a cleared registry.
- **The migration guide.** Once the warnings exist, the guide's old calls warn; hiding them after the first must not hide another warning, so the chunks that show the Class A fixes keep their warnings.
- **clang-format** may change more than whitespace (comments, namespace closers); the configuration turns those off, and the whitespace-free comparison catches the rest.
- **DEC-044.** A memory fix in the engine that changed any bit is not allowed; the exception may stay, documented with the paired measurements.
- **Drift during the phase.** A CRAN release of lme4 or Matrix would make the lme4-backed cases skip on CI's macOS and Windows jobs (listed, not hidden) while the pinned Linux job still runs them; `ubuntu-latest`'s move to Ubuntu 26 on 2026-10-19 is avoided by pinning.
- **Time.** The final reports take about 1.5 hours of computing (F14), and the CI iterations depend on the runners' queues.
- **The site.** The 404 note stays until the owners publish the site or drop the address.
