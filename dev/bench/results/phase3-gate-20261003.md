## Summary

- `logis_fe()` fits are faster than the reference's in every scenario: the median time is 29% to 64% lower with SerBIN and 21% to 32% lower with BAN. Peak memory is lower or within 5% (`bin-1e5-m10000-p5`: 361 MB against 345 MB); with 50 covariates on 1e6 observations it is 2041 MB against 2102 MB.
- The final comparison with the baseline flags 4 time regressions and 1 rerun; one of them is `logis_cre`, whose code the rewrite has not changed. Measured alternately with the reference in the same session (DEC-038), none regresses: every ratio lies between 0.97 and 1.02. The flags measured the machine's drift since the baseline.
- Old methods on old `logis_fe` objects rebuild the model on every call (DEC-032), which costs about 0.02 s at n = 1e5 and 0.19 s at n = 1e6. At the benchmark's sizes every difference is under DEC-023's 0.05 s floor, but methods the reference runs in under a millisecond are many times slower in relative terms, and at n = 1e6 they are slower by about 0.2 s per call. This is the documented exception DEC-039; the new functions on a `fit_logistic_fe()` model have no such cost.

## What the first run found, and the changes

The first run flagged 8 regressions and 3 reruns. Two were real:

- Old methods on old objects: the rebuild went through `data_prepare()` (about 0.36 s at n = 1e5), so `summary(test = "wald")` took 0.33 s against 0.0006 s, `test(test = "wald")` 0.31 s against 0.004 s, and `SM_output(stdz = "indirect")` 0.35 s against 0.015 s.
- Peak memory of `logis_fe` with 50 covariates on 1e6 observations: 2572 MB against 2102 MB (+22%). `data_prepare()` held up to five copies of the design matrix, and the D-38 rank check three more; R collects them lazily, so they added to the peak.

The changes, each checked to give identical results:

| Commit | Change | Check |
|---|---|---|
| `f528571` | The rebuilt model's data are built directly from `data_include`, not through `data_prepare()`; `data_include` no longer copies the design to drop its attributes | Identical models on the 72 old objects of the reference cases; a test against `data_prepare()` |
| `94859ce` | `data_prepare()` skips `data[rows, ]` when every row is complete, `na.omit()` when nothing is missing, the intercept column for numeric covariates, and row subsets that select every row in order | Identical `pprof_data` objects on 1185 comparisons (12 formula shapes, missing and transformed values, screening, sorted and unsorted providers, the reference datasets) |
| `01a9db7` | The rank check builds the within-provider matrix column by column and passes it to `qr()` without dimnames; the finiteness check uses `range()` | Bitwise identical matrix, rank, pivot, and QR on 40 random designs, including collinear ones |
| `82c75ed` | Provider factors are built with an integer `match()` instead of `factor()`, which converts every index to a string | A test against `factor()`; the reference suite |
| `35901f1` | The rebuild converts only the distinct provider IDs to strings | Identical models on the 72 old objects |

## Final run against the baseline

`comparison-20261003-windows.md`: 47 tasks, 4 regressions and 1 rerun by DEC-023's rule, all time; no memory regression.

| Scenario | Task | Baseline median s | New median s | Median ratio | Fastest ratio | Status |
|---|---|---|---|---|---|---|
| bin-1e4-m100-p5 | logis_cre | 8.56 | 9.84 | 1.15 | 1.15 | regression |
| bin-1e5-m1000-p5 | confint[option=gamma] | 19.6 | 22.1 | 1.12 | 1.11 | regression |
| bin-1e5-m1000-p5 | SM_output[stdz=direct] | 3.29 | 3.93 | 1.19 | 1.13 | regression |
| bin-1e5-m1000-p5 | test[test=score,score_modified=FALSE] | 3.10 | 3.53 | 1.14 | 1.12 | regression |
| bin-1e4-m100-p5 | confint[option=gamma] | 1.94 | 2.19 | 1.13 | 1.08 | rerun |

`logis_cre` is the reference's own code, unchanged in the working tree. The other four run the same computation as the reference in the same order: `confint()` the same `uniroot()` calls on the same functions of `poibin`, the standard score test and the direct expectations the same per-provider loops in the new C++ core.

## Paired re-measurement (DEC-038)

`paired-20261003-windows.md`: the five flagged tasks, and `logis_re` on `bin-1e4-m100-p5` as a control, measured in two rounds that alternate the reference and the working tree. No task regresses: in both rounds every ratio of the working tree's median and fastest run to the reference's lies between 0.97 and 1.02, and peak memory is equal or lower.
