## Summary

- No task regresses in time. The comparison flags none in time and marks one for a rerun, the `logis_re` fit on `bin-1e5-m1000-p5` (median 62.7 s, fastest 53.8 s, against 52.8 s and 52.7 s): measured alternately with the reference it takes the reference's time (ratios 0.997 and 0.982 for the median, 0.99 and 1.00 for the fastest run); the reference itself now takes 62.4 to 64.1 s, the drift DEC-038 guards against, as at the Phase 5 gate. Phase 6 does not touch the fits.
- The plot functions Phase 6 replaced, measured alternately with the reference: `bar_plot()` is faster (median ratios 0.49 and 0.86), `caterpillar_plot()` takes the reference's time (0.92 and 0.99), `plot()` of a `linear_fe` fit is at most 0.013 s slower (0.098 s against 0.085 to 0.095 s; its peak memory is half the reference's), and `plot()` of a `logis_fe` fit is as fast on 1e4 observations (ratios 1.05 and 1.03) and 0.032 to 0.046 s slower on 1e5 (0.147 to 0.157 s against 0.111 to 0.115 s), below DEC-023's 0.05 s threshold.
- Every memory flag (52 in the comparison, 4 in the paired run) is the transient of the dependencies' load order accepted at the Phase 4 gate (DEC-044): the peak before each task runs is a median 66.7 MB above the baseline's, and 1.4 MB below the Phase 5 working tree's, so removing dplyr, magrittr, rlang, and tidyselect from Imports did not change it; the tasks themselves add at most 13.6 MB more than the reference's (the linear RE measures, as at Phase 5).

## The comparison

`comparison-20261004-windows-phase6.md` compares 83 tasks (two of the 85 were not measured in both runs: `linear_fe` on `lin-1e5-m100-p5`, skipped in every run because the reference's dense centering matrices would not fit in memory, as in the baseline; and `plot()` of a `linear_fe` fit, which the Phase 5 supplement failed to measure, now measured in the working tree, a status change). It flags 52 tasks, all in peak memory, and marks one for a rerun.

## Where `plot()` of a `logis_fe` fit spends its time

On `bin-1e5-m1000-p5`, timed on a release build of the working tree (`R CMD INSTALL --preclean` into a scratch library; medians): the whole call 0.150 s; rebuilding the model from the old object 0.022 s; `standardize_providers()` 0.016 s; `test.logis_fe(test = "score")`, which the wrapper calls for the flags and which rebuilds the model again, 0.038 s (the test on a model, `test_providers(test = "score")`, 0.013 s). About 0.04 s of the difference from the reference is the two rebuilds, the cost DEC-039 accepts for the old methods on old objects since Phase 3, when this wrapper was written; Phase 6 changed only its data preparation, from dplyr to base R. Building the model once in the wrapper is a candidate for Phase 8, which revisits DEC-039.
