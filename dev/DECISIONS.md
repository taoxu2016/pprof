### DEC-001: Default `threads = 1` in every function

- Date: 2026-10-02
- Status: accepted (brief §3.5)
- Context: The reference defaults to `threads = 2` in `SM_output()` for the logistic models, hard-codes 4 in logistic RE/CRE `confint()`, and defaults to 1 elsewhere. CRAN allows at most 2 cores in examples and tests.
- Decision: Every function defaults to `threads = 1`, and thread counts are never hard-coded. This is a computational setting rather than a Class B change, because results must agree across thread counts within Tier 1/2 tolerances.
- Alternatives considered: Keep each function's reference default. This was rejected because it's inconsistent, and the hard-coded 4 violates CRAN policy.
- Consequences: The fixture generator passes `threads = 1` explicitly. The migration guide notes the change.

### DEC-002: The reference is the CRAN 1.0.3 tarball, identical to commit 5260838

- Date: 2026-10-02
- Status: proposed
- Context: Brief §3.1 asks Phase 0 to confirm that CRAN 1.0.3 corresponds to `main` at `5260838`.
- Decision: The reference is the CRAN tarball `pprof_1.0.3.tar.gz` (MD5 `6fa1344f4a265811059d27a105d06d6b`, as listed in the CRAN `PACKAGES` index). It is identical to `5260838` in `R/`, `src/`, `tests/`, `data/`, `man/`, and `NAMESPACE`; `DESCRIPTION` differs only by `R CMD build` normalization (`dev/design/audit/output/01_cran_identity.log`). The fixture generator installs this tarball, after checking its MD5, into an isolated library.
- Alternatives considered: Installing from the git commit. Equivalent in content, but the tarball is the published artifact and carries a checksum.
- Consequences: `dev/design/audit/install_reference.R` becomes the basis of the Phase 1 installer.

### DEC-003: One formula grammar and a `provider` argument for every family

- Date: 2026-10-02
- Status: proposed (open question M-6 asks which legacy interfaces must survive)
- Context: The reference has three input formats; the provider is an `id()` term for FE models, a `(1 | id)` term for RE models, and a column name for CRE models, and FE formulas are parsed with regular expressions (D-18). Brief §5.5 asks Phase 0 to choose between a formula special and a dedicated argument.
- Decision: New fitting functions take `formula` (response and covariates only, parsed with `terms()` and `model.matrix()`), `data`, and `provider` (one string naming a column of `data`), identically for FE, RE, and CRE models. CRE models add `within_between`. The compatibility wrappers accept all three reference formats and translate them.
- Alternatives considered: A formula special such as `provider(id)`, parsed with `terms(specials = )`. Idiomatic, but it mixes the grouping structure into the covariate formula, and for RE models it would sit next to lme4's own syntax. Keeping the vector interface in the new API was also rejected: a data frame is a cheap requirement, and it keeps a single validation path.
- Consequences: Transformations, interactions, and factor levels with spaces work in every family (fixing D-18). lme4 formulas are generated by the adapter, in the reference's term order (K-50), so lme4 results stay identical.

### DEC-004: S3 class hierarchy

- Date: 2026-10-02
- Status: proposed
- Context: Brief §5.2 allows at most one intermediate class, only where it removes real duplication.
- Decision: `pprof_model` is the base class. The four lme4-backed models share the intermediate class `pprof_mixed` (adapter, variance components, conditional SDs, printing). Firth is `c("pprof_logistic_firth", "pprof_logistic_fe", "pprof_model")`, so it inherits the logistic FE inference as the reference does (D-12, pending M-2). The FE models have no intermediate class. Results have their own classes (`pprof_provider_tests`, `pprof_measures`, `pprof_profile`, `pprof_funnel`, and so on; NAMING.md §5).
- Alternatives considered: Flat classes with shared helpers only (more boilerplate methods); `pprof_logistic_cre` inheriting from `pprof_logistic_re` (would leave no room for `pprof_mixed`, and linear CRE differs from linear RE in its standard errors, K-69 versus K-70).
- Consequences: If M-2 is answered "no", Firth drops the intermediate class and declares its own capabilities.

### DEC-005: Compact model objects; covariate-dependent methods take `data`

- Date: 2026-10-02
- Status: proposed
- Context: Reference objects carry the whole processed data and character row names: about 15 times the size of what downstream methods need (ARCHITECTURE §D.1, B5). Brief §5.2 asks Phase 0 to decide whether to keep covariates for the methods that need them.
- Decision: Objects keep the compact per-observation vectors of ARCHITECTURE §D.1 (at most 24 bytes per observation for FE models, 32 for RE/CRE) and keep the design matrix, processed data, and lme4 fit only with `keep_data = TRUE`. The three methods that need covariates (standard provider score test, covariate LR and score tests) take `data`, rebuild the design with the stored `terms` and settings, and verify the rebuild against the stored linear predictor before computing; otherwise they raise `pprof_error_data_required`. Compatibility wrappers fit with `keep_data = TRUE`.
- Alternatives considered: Always keeping the design matrix (simpler, larger); recovering data from the call environment (fragile).
- Consequences: The verification step makes a mismatched `data` an error rather than a silent wrong answer.

### DEC-006: R/C++ boundary

- Date: 2026-10-02
- Status: proposed
- Context: Brief §5.6 requires measured evidence for what stays in C++.
- Decision: Keep in C++, rewritten as an Rcpp-free core with thin adapters: SerBIN, BAN, Firth, the variance block inverse, the standard score test, and direct-standardization expectations. Move linear FE to direct demeaning in R. Keep everything else in R. Evidence in ARCHITECTURE §F (B1 to B4).
- Alternatives considered: Porting the logistic engines to R (the ports exist and reproduce the path, but are 1.6–2.3× slower and allocate hundreds of megabytes per fit); a C++ linear FE (unnecessary once demeaning removes the O(Σn_i²) cost).
- Consequences: The linear FE change must pass the reference suite at Tier 1 (B2 shows 1.5e-14 agreement on beta).

### DEC-007: One information-block routine with caller-supplied weights

- Date: 2026-10-02
- Status: proposed
- Context: The block information computation exists in eight places (ARCHITECTURE §A.2), each with slightly different weight handling (K-13, K-20, K-31, K-66). Brief §5.6 requires one shared, tested routine.
- Decision: `src/core/information_blocks` computes the diagonal, cross, and β blocks and the Schur complement from weight vectors passed in by the caller (separately for the diagonal, cross, and β blocks where the reference differs). Each caller passes the weights the reference used.
- Alternatives considered: One routine with one weight convention, which would change results (Class B).
- Consequences: The differences between callers become visible parameters, each tested.

### DEC-008: Quiet by default in the new API

- Date: 2026-10-02
- Status: proposed
- Context: The reference's `message = TRUE` default prints per-iteration logs and screening notices; `linear_fe` and the RE fits print with no way to stop them (D-36). Brief §5.5 asks for one verbosity argument with no output when it is off.
- Decision: New functions take `verbose = FALSE`. Screening results and convergence diagnostics are stored in the object and shown by `print()`. Non-convergence and screening exclusions still raise classed warnings (`pprof_warning_not_converged`, `pprof_warning_screening`), which are not suppressed by `verbose = FALSE`. Compatibility wrappers keep the reference's messages.
- Alternatives considered: `verbose = TRUE` (noisy for a modeling function, unlike `lm` and `glm`).
- Consequences: A presentation change, recorded in the migration guide.

### DEC-009: Dependency set

- Date: 2026-10-02
- Status: proposed
- Context: Brief §7; ARCHITECTURE §H and V16.5.
- Decision: Remove `RcppParallel`, `caret`, `olsrr`, `pROC`, `dplyr`, `tidyselect`, `magrittr`, and `globals` from Imports and `Matrix` from Imports (it remains installed through lme4). Add `generics`. Keep `Rcpp`, `RcppArmadillo` (LinkingTo), `lme4`, `poibin`, `ggplot2`, `scales`, `tibble`. `rlang` only in presentation code if Phase 6 needs it. Each replaced function (`pROC::auc`, `caret::nearZeroVar`, `olsrr::ols_vif_tol`) gets an equality test against the original before removal.
- Alternatives considered: Keeping `pROC` (one function, prints messages); moving `ggplot2` to Suggests (plots are core functionality).
- Consequences: The install tree shrinks from 131 to 38 packages; `SystemRequirements: GNU make` and TBB linking go away.

### DEC-010: `check_data()` reports instead of stopping

- Date: 2026-10-02
- Status: proposed
- Context: `data_check()` stops on any missing value while the fits delete incomplete rows (D-17), and reports only through messages.
- Decision: The new `check_data(formula, data, provider)` returns a `pprof_data_check` object (missingness by column and overall; zero and near-zero variance with the `caret` thresholds; pairwise correlations above 0.9; VIF ≥ 10) with a print method. The `data_check()` wrapper keeps the reference behavior.
- Alternatives considered: Keeping the stop (inconsistent with the fits).
- Consequences: Not a statistical change: no model result depends on it.

### DEC-011: `confint()` means covariate intervals

- Date: 2026-10-02
- Status: proposed
- Context: The reference's `confint()` returns provider-effect or standardized-measure intervals, unlike every other R model class.
- Decision: `confint.pprof_model()` returns covariate intervals with the family's rule. Provider-level intervals come from `provider_effects(interval = )` and `standardize_providers(interval = )`. Old classes keep the old meaning through the wrappers.
- Alternatives considered: Keeping the reference meaning (surprising to R users; mixes two estimands in one generic).
- Consequences: Listed in the migration guide.

### DEC-012: Result objects are validated lists with a table and named settings

- Date: 2026-10-02
- Status: proposed
- Context: Reference results are data frames or matrices with string attributes (`"provider size"`, `"model"`, `"description"`, `"confidence_level"`), which plots parse (D-33), and flags are factors with data-dependent levels (D-15).
- Decision: Every result object is a list with a `table` (base data frame keyed by `provider_id` or coefficient name, with the column names of NAMING.md §5) and named fields for the settings used, built by `new_*()` and checked by `validate_*()`. Flags are integers -1, 0, 1. `tidy()` returns the table as a tibble. Plots read only these fields.
- Alternatives considered: Data-frame subclasses with attributes (attributes are lost on subsetting).
- Consequences: Presentation change only; wrappers rebuild the old shapes.

### DEC-013: Compatibility wrappers reproduce the reference, including items awaiting sign-off

- Date: 2026-10-02
- Status: proposed
- Context: Brief §8 requires wrappers that return the old output shapes, warn once per session, and stay for at least one minor release.
- Decision: Wrappers live in `R/compat-*.R`, translate arguments, call the new API with `keep_data = TRUE`, convert results to the exact old shapes (BEHAVIOR_SPECS §16), and keep the new model in `attr(, "pprof_model")` for the old methods. They reproduce every Class B behavior awaiting sign-off (D-10, D-12, D-13, D-24, D-31, D-32, D-34) and apply Class A fixes. Deprecation warnings use an internal once-per-session helper with class `pprof_deprecated`, without a `lifecycle` dependency.
- Alternatives considered: Wrappers returning new objects (would break user scripts).
- Consequences: Signed-off Class B changes apply to the new API; whether wrappers also adopt them is decided per item.

### DEC-014: Fixtures record iteration counts parsed from the reference's log

- Date: 2026-10-02
- Status: proposed
- Context: The reference returns no iteration count, but Tier 2 equivalence should check that the iteration path is reproduced, not only the estimates (brief §3.4).
- Decision: The fixture generator captures the C++ output for logistic FE and Firth fits and stores the parsed iteration count, as the Phase 0 audit does (V10.1, V12.1). The rewrite's convergence diagnostics must match it exactly (Tier 0).
- Alternatives considered: Comparing estimates only (cannot distinguish a reproduced path from a different path that lands close by).
- Consequences: A change in iteration count is a test failure that needs a register entry.

### DEC-016: roxygen2 version

- Date: 2026-10-02
- Status: proposed
- Context: The reference was documented with roxygen2 7.3.3 (`RoxygenNote: 7.3.3`). The development machine has roxygen2 8.1.0, which on `devtools::document()` rewrites `NAMESPACE` (grouped `importFrom()` directives) and `DESCRIPTION` (`Config/roxygen2/version` instead of `RoxygenNote`). At the Phase 0 gate the rewrite changed nothing in `R/`; the parsed namespaces before and after were identical (86 imports, same exports, S3 methods, and dynamic libraries), and `man/` did not change.
- Decision: Do not commit roxygen-only reformatting while `R/` is unchanged. Adopt roxygen2 8.1.0 (or later) at the start of Phase 2, in one commit that contains only the regenerated files, and record the version in CI.
- Alternatives considered: Installing roxygen2 7.3.3 locally (keeps old formatting but pins an outdated tool).
- Consequences: Phase 1 gate checks restore the two files after `document()` as Phase 0 did, or Phase 2 adopts 8.x first.
