# validation/

Large or slow equivalence checks that do not ship with the package (the folder is in `.Rbuildignore`).

| Path | Contents |
|---|---|
| `fixtures/reference/` | The full reference fixture set: cases too large or slow for the shipped core set (the binary-example algorithm grid, default-size bootstrap tests, an 80,000-row simulation for D-24). Generated by `dev/reference/generate_fixtures.R`; never edited by hand |
| `fixtures/cox/` | The full set of Cox fixtures (pprof_py v0.7.0 and the pinned `survival` and `glmnet`): the cases too large for the shipped core set (DEC-096). Generated by `dev/reference/cox/generate.py`; never edited by hand |
| `fixtures/pprofr/` | The pprofR fixtures, the full set only (DEC-152, DEC-153): pprofR 0.2.0's results (commit `f23c288`) on eleven synthetic cases, with their data. Generated by `dev/reference/pprofr/generate.R`; never edited by hand |
| `fixtures/data-prepare-snapshot.rds` | The signatures of the `pprof_data` objects that every reference case builds, recorded by `dev/tools/data_prepare_snapshot.R` before the CoxPH phase changed the data layer; `tests/testthat/test-data-prepare-snapshot.R` compares the code with them (COXPH_DESIGN §C.2) |
| `cox-calibration-report.md` | The calibration of the Cox tolerance tiers against the Cox fixtures (`dev/reference/cox/calibrate.R`, DEC-097) |
| `run-cox-reference.R` | Runs the Cox reference tests on both Cox fixture sets and the engine-identity tests of the survival and glmnet adapters, with `NOT_CRAN` set, recording each comparison's ratio to its tier (`expect_cox_tier()`, `tests/testthat/helper-cox-fixtures.R`), and writes the Cox equivalence report; exits with status 1 on any failure (DEC-135). CI's `rewrite-reference.yaml` runs it on every platform |
| `cox-equivalence-report.md` | The latest Cox report: the comparisons with pprof_py v0.7.0, survival, and glmnet by file, case, tie method, and tier, with the largest ratio of each; the differences a register entry decides; providers near a flag threshold; the engine identity; the calibration's result; and the register's CoxPH entries, with the Class B items awaiting a methodology owner marked |
| `pprofr-calibration-report.md` | The calibration of the comparisons with pprofR against independent references and negative controls (`dev/reference/pprofr/calibrate.R`, DEC-158) |
| `run-pprofr-reference.R` | Runs the pprofR reference tests (`test-pprofr-reference.R`) on the pprofR fixtures with `NOT_CRAN` set, recording each comparison's ratio to its tier (`expect_pprofr_tier()`, `tests/testthat/helper-pprofr-fixtures.R`), and writes the pprofR equivalence report; exits with status 1 on any failure (DEC-159). CI's `rewrite-reference.yaml` runs it on every platform |
| `pprofr-equivalence-report.md` | The latest pprofR report: the comparisons by case and tier with the largest ratio of each, the differences a register entry decides, providers near a flag threshold, the calibration's result, and the register's entries of the logistic extensions phase |
| `run-reference.R` | Replays both fixture sets (core and full) against the in-repo package and writes the equivalence report |
| `equivalence-report.md` | The latest report: per-case outcome, largest absolute and relative differences (including values in attributes, such as the lme4 components of RE fits), how many long double vectors stored as signatures are bitwise identical, and the providers whose reference p-value lies within tolerance of a flag threshold (brief §3.4). Cases of Class A fixes are compared with their per-case expectations (`tests/testthat/helper-reference-overrides.R`, DEC-022) and marked with their register entry |
| `run-differential.R` | Differential testing of the fitting functions and their methods (Phase 3 for logistic fixed effects, Phase 4 for the other fits, Phase 5 for the methods of the other fits): seeded random binary datasets (provider counts and sizes, event rates, providers with no events or only events, the number of covariates) for `logis_fe()`, `logis_firth()`, `logis_re()`, and `logis_cre()`, seeded random linear datasets (small providers, a covariate that varies between providers, missing outcomes) for `linear_fe()`, `linear_re()`, and `linear_cre()`, and datasets of both kinds with character IDs whose collation order differs from their numeric order; the methods run over the grid of alternatives, `level`, nulls, and `parm`; every function and method runs on the pinned reference library in a separate R session and on the working tree, and the results are compared with the fixtures' tolerance tiers |
| `differential-report.md` | The latest differential report |
| `run-simulation.R` | The simulation study of the provider tests and intervals with known truth (DEC-053): for each family, data without provider effects and with six outlying providers, fit at the defaults, with the size and power of the default test and the coverage of its intervals; from CoxPH Phase C6, the Cox model stratified by provider, with its mid-p and exact tests and a scenario of small providers (DEC-134). Informational: it gates nothing |
| `simulation-report.md` | The latest simulation report |

Run from the repository root:

```sh
Rscript validation/run-reference.R
Rscript validation/run-cox-reference.R           # glmnet for the penalized cases
Rscript validation/run-pprofr-reference.R
Rscript validation/run-differential.R            # needs dev/reference/lib (dev/reference/setup_reference_library.R)
Rscript validation/run-simulation.R              # about 35 minutes
```

The core set also runs as part of `devtools::test()` (slow cases skip on CRAN). Comparisons of lme4-backed results run only when the installed lme4 and Matrix versions equal those in the fixture manifest; otherwise they are reported as skipped, so that version sensitivity is documented rather than hidden by tolerances (brief §3.1).
